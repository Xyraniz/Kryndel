# Qt 6 native package for Kryndel

This is an early native integration prototype. It calls Qt's C++ libraries through the `kry_qt6` C ABI adapter; it does not start CPython or import PyQt6. It requires 45 base modules from the PyQt 6.11 module inventory. CMake also links Qt ActiveQt on Windows and Qt WebEngine on supported kits when their optional components are installed. The selected kit used to validate this prototype has ActiveQt but not WebEngine. WebEngine constructors and supported direct methods are generated from its optional PyQt SIP source; the selected Qt kit lacks WebEngine headers, so those bindings are not compiled or runtime-validated here.

## Build the adapter

Required build tools are CMake 3.21 or later, a C++17 compiler, and Qt 6.11 development packages for the 45 base modules listed in `native/CMakeLists.txt`. On Windows, install the matching Qt ActiveQt add-on to include QAxContainer; install the WebEngine add-on on any supported platform to include its available Core, Quick, and Widgets components. The bridge builds each module's constructor factory in a separate C++ translation unit so Qt modules with colliding global class names do not share headers in one translation unit. Qt Charts and Qt Graphs still produce duplicate `QAbstractSeries` RTTI sections when linked into the same MinGW adapter; simultaneous runtime type behavior for these two modules is not validated. The adapter links its matching Qt runtime libraries, plus the platform plugins used by the application.

```powershell
cmake -S packages/qt6/native -B build/qt6 -G Ninja `
  -DCMAKE_CXX_COMPILER="C:/Qt/Tools/mingw1310_64/bin/g++.exe" `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.11.0/mingw_64"
cmake --build build/qt6 --config Release
cmake --install build/qt6 --prefix dist/qt6
```

Use the compiler that matches the selected Qt kit. For MSVC, select the matching Visual Studio generator and Qt `msvc2022_64` prefix instead. Installation places the shared adapter and its C header in the chosen prefix. At runtime, make the adapter, its Qt shared libraries, and the platform plugins available to the application. The adapter currently depends on Qt Test for `QSignalSpy` signal capture.

## Kryndel API

Import `packages/qt6`, load the adapter with `open(path)`, and call `start` before creating objects. `constructors(runtime)`, `meta_classes(runtime)`, and `describe_class(runtime, name)` work before `start`: they list constructible classes, linked QObject meta-objects, and static Qt properties, invokable signatures, enums, and flags. `new` takes a Qt class name, constructor arguments encoded as a JSON array, and an optional parent handle (`0` means no parent); `new_default` uses an empty argument list. Unique class names accept their short form, such as `QPushButton`. When more than one module provides a constructible class with the same name, use the module-qualified name, such as `QtCharts.QChart` or `QtGraphs.QChart`. The generated factory covers constructible QObject, QWidget, QWindow, QLayout, and Qt 3D QNode classes with default or standard-parent constructors. For argument constructors, `new` tries generated native wrappers from public PyQt SIP declarations, then constructors registered in Qt's meta-object system with `Q_INVOKABLE`. Generated wrappers accept only signatures with supported JSON conversions. `get` and `set` access Qt properties. `call` invokes a public slot or `Q_INVOKABLE` method by its normalized C++ signature, with direct wrappers for selected C++ APIs described below. QObject arguments are JSON objects containing `object_id`. `connect` subscribes to a signal signature, and `events` processes GUI events and returns captured signals. `describe` returns the same meta-object data for a live QObject. Call `shutdown` before `close` to destroy managed objects on the application thread.

`call_static(runtime, "QtCore.QRegularExpression", "escape(QString)", "[\"a.b\"]")` calls a generated static method and returns a JSON string whose decoded value is `a\.b`. Use a module-qualified class name when Qt exposes the same class name from more than one module.

`value_types(runtime)` lists default-constructible Qt `Q_GADGET` types plus ordinary value classes with generated constructors or methods. `describe_value_type(runtime, name)` reports a gadget's static meta-object or the generated native method signatures before application startup. `value_new` creates a default `QtValue`; `value_new_args` selects a generated native constructor, for example `value_new_args(runtime, "QDate", "[2025, 12, 1]")`. `value_get` and `value_set` expose reflected gadget properties. `value_call` invokes reflected gadget methods or generated native methods on ordinary value types, for example `value_call(runtime, date, "year()", "[]")`. `value_describe` reports the reflected or generated method surface of a live value. Use `value_json` to pass a value handle to a Qt property or method, and `value_handle` to wrap a returned gadget handle. Ordinary values with a known JSON converter return their JSON shape; other generated value types return `{ "value_id": number, "type": string }` handles that can be passed to `value_call` or another compatible Qt method. Native bindings currently cover a selected set of ordinary values; this is not the complete PyQt value-type surface.

See [`../../examples/qt6_widgets.kry`](../../examples/qt6_widgets.kry) for a small Widgets application.

The bridge converts common Qt values at the JSON boundary: `QPoint`/`QPointF` and `QVector2D` use `{ "x": number, "y": number }`; `QVector3D`/`QVector4D` add `z` and `w`; `QLine`/`QLineF` use `x1`, `y1`, `x2`, and `y2`; `QSize`/`QSizeF` use `{ "width": number, "height": number }`; `QRect`/`QRectF` use `{ "x": number, "y": number, "width": number, "height": number }`; and `QMargins`/`QMarginsF` use the four named edges. `QGeoCoordinate` uses `latitude` and `longitude` fields with optional `altitude`; `QHostAddress` uses an IP address string; `QNetworkRequest` uses `{ "url": string, "headers": { ... } }`. `QColor` uses a Qt color name or hexadecimal string. `QDate`, `QTime`, `QDateTime`, and `QUrl` use ISO/string forms; `QRegularExpression` accepts a pattern or pattern/options object; `QUuid` uses a UUID string; `QImage`, `QPixmap`, and `QIcon` accept a file path or `{ "png_base64": "..." }`; `QFont` uses `QFont::toString()` format; `QKeySequence` uses PortableText; and `QByteArray` uses `{ "base64": "..." }`. `QJsonValue`, `QJsonObject`, and `QJsonArray` map to their corresponding JSON shapes. `QVariantMap`, `QVariantHash`, and maps of strings use JSON objects; QVariant map values retain their JSON types, while string-map values must be strings. Signed and unsigned 64-bit values use exact JSON numbers up to 9,007,199,254,740,991; larger values use decimal strings, which can also be passed as inputs. `QVariant` accepts and returns supported JSON scalars, objects, arrays, or null. Meta-object enum arguments accept a key name or integer and return as an integer. Values returned from Qt use the corresponding shape.

The adapter also has direct operations for common widget geometry, container, file, settings, and ActiveX APIs. Widgets support `move`, `resize`, `setGeometry`, size constraints, and geometry getters. Layouts and composites include `QGridLayout.addWidget`, `QFormLayout.addRow`, `QWidget.setLayout`, `QMainWindow` central/menu/toolbars/docks, `QStackedWidget.addWidget`, `QSplitter.addWidget`, `QScrollArea.setWidget`, `QGraphicsScene.addWidget`, `QGraphicsView.setScene`, `QTextEdit.setDocument`, `QWizard.addPage`, undo views, button groups, tabs, menus, and toolbar actions. Item widgets support simple string entries with `QListWidget.addItem`, `QTreeWidget.addTopLevelItem`, and `QTableWidget.setCellText`/`cellText`; these helpers avoid exposing Qt's non-QObject item handles. When ActiveQt is linked, `QAxObject` and `QAxWidget` support control selection, dynamic calls, sub-object queries, property bags, and verbs. `QIODevice` supports basic open/read/write/seek/close calls with `QByteArray` values; `QSettings` supports key access and sync; `QFileSystemWatcher` supports path registration; and `QProcess` exposes captured stdout/stderr. Calls still use Qt signatures, for example `call(runtime, layout, "addWidget(QWidget*)", "[...]")`.

`QVariant` arguments use JSON values directly. For example, `QTabBar.setTabData(int,QVariant)` accepts an object and `tabData(int)` returns that object as JSON.

## Current coverage

The [generated PyQt 6.11.0 API inventory](api_inventory.json) records 52 modules, 1,444 classes, 2,452 constructor signatures, 23,529 method signatures, 2,860 signal signatures, 1,137 enum declarations, and 9,892 documented enum values. The adapter links 45 base modules and conditionally links ActiveQt and WebEngine, has 94 explicit partial constructor entries, checks 1,256 default-factory candidates, and probes 1,318 classes for Qt meta-objects. Qt-registered invokable constructors are discovered at runtime. `constructors(runtime)` is the exact list available for a built adapter. The inventory is a reference for follow-up work, not an implementation coverage claim. The generator uses only Python's standard library during development; neither Python nor PyQt is needed by Kryndel applications.

The SIP-based native generator currently emits 10,048 direct QObject method overload wrappers across 48 modules, 5,963 ordinary Qt value method wrappers across 75 shards, 944 QObject argument-constructor variants across 61 shards, and 1,168 ordinary value constructor variants across 73 shards. Value-method wrappers were generated for 455 value classes; the runtime advertises only Qt types that are copyable and registered with `QMetaType`. Passing a Qt value as an argument also requires default construction so the bridge can extract it from `QVariant`. These generated constructors and methods cover mapped native JSON conversions, including primitives, common Qt values, 64-bit integers, `QVariant`, variant and string maps, Qt enums and flags, QObject handles, and common Qt lists. Unsupported signatures are omitted. These counts describe a generated partial native surface, not every documented PyQt constructor, method, or overload.

To regenerate, download the release's [`module_index.html`](https://riverbankcomputing.com/static/Docs/PyQt6/module_index.html) and [`sip-classes.html`](https://riverbankcomputing.com/static/Docs/PyQt6/sip-classes.html), then run `tools/generate_inventory.py --modules-html <path> --classes-html <path> --include-signatures --cache-dir <cache-path>`. Class documentation pages are downloaded into the cache and reused on later runs. The script checks the pinned documentation version, writes the API inventory, generates the shared constructor interface, and writes one module-specific default constructor factory source under `native/generated_modules/` for each linked module. To regenerate direct method and argument-constructor sources from the PyQt 6.11.0 source distribution, run `tools/generate_native_methods.py --sip-root <path-to-pyqt-6.11.0/sip>`; pass `--extra-sip-root <path-to-addon/sip>` once for each separately distributed PyQt add-on, including WebEngine when its source declarations are available. The generator maps documented Python union aliases such as `bytes | QByteArray` and `datetime.datetime | QDateTime` to their typed C++ declarations. It writes separate QObject method, QObject constructor, ordinary value method, and ordinary value constructor shards, which the adapter's CMake project includes.

Qt meta-object reflection exposes properties, signals, enums, slots, methods, and constructors explicitly marked invokable by Qt. Most public C++ methods are not reflected. The selected Qt kit exposes meta-objects for 469 non-QObject types, while generated direct bindings currently cover methods on 455 value classes and constructors for copyable registered values. Other non-QObject APIs, constructors, and types still need bindings. The value converters listed above cover only a small common subset; other supported values are returned as typed handles. This package is not complete PyQt6 coverage. See [`../../docs/qt6-native.md`](../../docs/qt6-native.md) for the completion requirements and gaps.
