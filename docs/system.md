# System integration guide

Kryndel exposes a small typed system boundary rather than a general host-language escape hatch. The stable registry includes `fs_read_text`, `fs_write_text`, and `env_get` in addition to the bounded thread and channel primitives.

`fs_read_text(path)` reads exact bytes, validates UTF-8, closes the stream, and returns `Result[String, String]`. `fs_write_text(path, text)` writes the exact UTF-8 bytes carried by the String value, closes the stream, and returns `Result[Nil, String]`. Embedded NUL bytes in paths are rejected so the source-level path cannot be silently truncated by a C API. File content may contain NUL bytes only when it is valid UTF-8 text; its length remains explicit and lossless.

`env_get(name)` returns `some(value)` for a present, valid UTF-8 environment variable and `none` when the variable is absent. Names containing NUL are runtime errors because host environment APIs use terminated strings; invalid UTF-8 environment values are rejected rather than becoming invalid `String` values. The API does not mutate the process environment, execute commands, or expose file descriptors.

Modules remain source-relative and reject absolute paths, parent traversal, artifacts, missing files, duplicate exports, and cycles. Filesystem APIs use trusted local mode by default. `--restricted ROOT` enables a documented restricted mode that rejects absolute paths and `..`, canonicalizes existing paths, prevents symlink escapes from the root, and requires the destination parent to remain inside the root. The native launcher selects a C11 compiler and links the math and pthread libraries. `kry doctor` reports compiler availability, required linked libraries, source-tree completeness, output-directory writability, locale configuration, and builtin-registry completeness.

Source and artifact inputs are bounded by safe defaults of 16 MiB and 64 MiB respectively; `--max-source` and `--max-artifact` allow a caller to choose stricter per-invocation limits. Resource failures produce categorized diagnostics before parsing or execution. Process creation, sockets, terminal control, signals, raw pointers, dynamic libraries, and FFI are outside the stable source API. Any future addition must specify type signatures, error values, ownership and cleanup, path or capability boundaries, platform support, deterministic tests, and documentation before implementation is accepted.
