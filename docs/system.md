# System integration guide

Kryndel exposes a typed system boundary rather than a general host-language escape hatch. The stable registry includes filesystem/environment operations, process metadata, HTTP/WebSocket requests, SQLite, raw TCP/UDP, FFI, display/camera capture, IP geolocation, and platform-specific Windows operations in addition to bounded threads and channels.

`fs_read_text(path)` reads exact bytes, validates UTF-8, closes the stream, and returns `Result[String, String]`. `fs_write_text(path, text)` writes the exact UTF-8 bytes carried by the String value, closes the stream, and returns `Result[Nil, String]`. Embedded NUL bytes in paths are rejected so the source-level path cannot be silently truncated by a host filesystem API. File content may contain NUL bytes only when it is valid UTF-8 text; its length remains explicit and lossless.

`env_get(name)` returns `some(value)` for a present, valid UTF-8 environment variable and `none` when the variable is absent. Names containing NUL are runtime errors because host environment APIs use terminated strings; invalid UTF-8 environment values are rejected rather than becoming invalid `String` values. The API does not mutate the process environment, execute commands, or expose file descriptors; it is unavailable in restricted mode.

Modules remain source-relative and reject absolute paths, parent traversal, artifacts, missing files, duplicate exports, and cycles. Filesystem APIs use trusted local mode by default. `--restricted ROOT` confines module loading and sandbox-aware filesystem calls to `ROOT`, rejecting absolute paths, parent traversal, and symlink components. During restricted execution, Kryndel also denies builtins with unmediated host effects: environment, process, network, FFI, database, platform, graphics, Windows, host-clock reads, and Discord APIs. `process_run` is part of the stable API, but unavailable in this mode; it launches programs without a shell and bounds combined output. Standard output remains available. SQLite is disabled because SQL can attach another database path, and pure date parsing/formatting remain available. The restriction applies to interpreter execution only; it is not carried into standalone native executables. The Go executable uses no C compiler or external runtime. `kry doctor` verifies executable capabilities, limits, and builtin-registry completeness.

> [!WARNING]
> `--restricted ROOT` is a Kryndel capability restriction, not an operating
> system sandbox. Use OS-level isolation when running hostile code; the process
> still runs with the host user's privileges. The restriction applies only to
> interpreter execution; standalone native executables do not inherit it.

Source and artifact inputs are bounded by safe defaults of 16 MiB and 64 MiB respectively; `--max-source` and `--max-artifact` allow a caller to choose stricter per-invocation limits. The same execution context applies instruction, wall-clock, call-depth, memory, collection, channel, worker, and output budgets. Resource failures produce categorized diagnostics before parsing or execution. `process_run` is stable and executes without a shell, but is disabled by `--restricted`; the same restriction disables host-facing builtins that cannot be confined to `ROOT`. Process creation through Kryndel does not itself provide host-level isolation. Terminal control, signals, and arbitrary pointer arithmetic remain outside the stable source API; the implemented FFI surface is deliberately narrower than arbitrary native code. Any future addition must specify type signatures, error values, ownership and cleanup, path or capability boundaries, platform support, deterministic tests, and documentation before implementation is accepted.
