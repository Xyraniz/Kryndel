The source-level filesystem boundary is now implemented as a verified bootstrap API, a no-Python KEXE framing/checksum checker exists as a host-capability checkpoint, a first strict manifest reader exists in Kryndel source over that boundary, `stdlib/core/data.kry` provides bounded readers, a balanced string builder, and nominal toolchain records, the source manifest module emits canonical lockfile JSON for validated entries, `stdlib/core/bytecode.kry` verifies normalized bytecode records, `stdlib/core/runtime.kry` executes the verified runtime subset from `runtime-source-v1.json`, `stdlib/core/lexer.kry` reproduces the published lexer snapshot's kinds, text, order, spans, recovery cases, and tagged typed-literal payloads, `stdlib/core/parser.kry` consumes those tokens for a tested AST subset, `stdlib/core/checker.kry` validates typed literal assignments in that subset plus dependency traversal, `stdlib/core/compiler.kry` lowers that subset to bytecode records accepted by the source verifier, `stdlib/core/runtime.kry` executes the emitted subset end to end, `stdlib/core/artifact.kry` plus `stdlib/core/sha256.kry` validate the framing and digest of a KEXE payload in source-level tests, `stdlib/core/json.kry` decodes a bounded bytecode schema from strings, payload bytes, or controlled `fs.read_text`, and a differential pipeline runs a real KEXE through source framing, hashing, decoding, verification, and runtime. The direct backend lowers constant-return and one conditional-jump program. `tools/kry-format`, `tools/kry-kexe-check`, `tools/kry-bundle-check`, and `tools/kry-seed-check` provide narrow no-Python host utilities, but the source modules remain compatibility seams under the Python VM, not native implementations.
The strict decoding and executable preflight checkpoint is complete under bootstrap Python. The next technical gate is native artifact-file integration, followed by full AST/precedence/checking parity, complete opcode/runtime coverage, and package/KEXE production replacement before claiming toolchain independence. The machine-readable `kry autonomy-audit` report is the required inventory for each subsequent migration checkpoint.
The value-layout, full bytecode-schema, source serializer, and KEXE framing
modules are verified source compatibility seams, not native runtime components. The bootstrap manifest parser remains the reference implementation and the
project must not claim independence from Python. The seed-only checker verifies
only the raw empty-main artifact and must not be described as a product bundle.
