# Kryndel source SHA-256 contract v1

## Alcance

`stdlib/core/sha256.kry` implementa SHA-256 sobre `Bytes` nominales usando sólo
operaciones aritméticas, arrays y funciones del lenguaje. Simula palabras de 32
bits con módulo `2^32`, implementa las rotaciones y funciones booleanas por
aritmética, aplica padding FIPS-180 con longitud big-endian y ejecuta las 64
rondas de compresión por bloque.

`digest(Bytes)` devuelve una cadena hexadecimal minúscula de 64 caracteres. La
operación `verify(Bytes, String)` devuelve `Ok` cuando coincide y
`Error("KRY6205 ...")` cuando el digest esperado no coincide. Los vectores
congelados en `tests/fixtures/sha256-v1.json` cubren entrada vacía, `abc` y una
frase que requiere más de un bloque.

| Propiedad | Garantía v1 |
| --- | --- |
| Entrada | `Bytes` válido, incluidos cero bytes |
| Digest | SHA-256 hexadecimal minúsculo, 64 caracteres |
| Determinismo | Mismos bytes producen el mismo digest |
| Dependencias | Sólo primitivas de Kryndel; no `hashlib`, Python ni host intrinsic |
| Error de comparación | `KRY6205` |
| Uso KEXE actual | Conectado por regresión a `core/artifact`; el reader extrae y canonicaliza bytes, mientras SHA-256 valida el payload |

## Límites

El módulo es una implementación fuente ejecutada por la VM Python y no reemplaza
la ruta normal de `hashlib` en artefactos, paquetes o CLI. La API todavía no lee archivos, no decodifica JSON ni serializa módulos. La
integración de KEXE se limita a pasar `Header.payload` y `Header.checksum_hex`
a `verify`; no retira el checksum Python de artefactos, paquetes o CLI. La
siguiente ampliación debe decodificar el payload JSON y construir un
`ModuleRecord` validable, manteniendo los casos negativos de payload manipulado.
